# Dissero local customizations

The About panel installs the latest stable DisseroHub release through the managed Windows service. A detached worker prepares a complete isolated checkout, retains dependencies, typechecks and builds before activation. A stable bootstrap uses exclusive commit/rollback decisions, verifies startup and client assets, and recovers interrupted activation. Strict loopback/same-origin requests, exact displayed-version matching and PTY admission gates protect the local operation. User data, source changes and external agent sessions are preserved. Development and unmanaged runs expose an explicit unsupported reason.

Office life is a separate local population: a receptionist and three residents use common areas on weekdays from 08:00 to 18:00 in the device timezone. The `ambientLife` preference and reduced-motion setting control this population, which shares spot reservations but stays outside real session inventories, activity, statistics, and playback.

Presence follows real execution boundaries. Codex retirement survives disposable trackers; stale locks, replayed history, late results, and compaction cannot reopen completed subagents or explicitly ended sessions. Explicit stops clear abandoned calls and approvals, and a monotonic turn-end timestamp rejects delayed old calls. Known live tool hooks track bounded pending calls by ID; pending work bypasses the quiet-turn heuristic. Published Claude shells prevent idle parking while modern background registry status remains authoritative. Fresh work, a new session, or recovery from a missing snapshot can cancel a visible exit before elevator entry. A per-character weak reference preserves the original exit timestamp and reason, so successive old rows cannot lower that threshold. Forced-offline and hidden-room guards remain in effect, and a terminal parent prevents an old child from entering. Existing source-staleness safeguards remain in place.
The **Central de trabalho** button opens an additive dialog with project summaries, an attention queue, task templates and integration diagnostics. `ui/work-center-model.ts` derives the overview only from structured session state; native asynchronous questions keep their original destination and direct requests reuse the existing permission card. Registered rooms remain visible without agents. Delivery reads reuse the existing terminal access guard, stop on close/access changes, and distinguish a recorded reply from validation. Replay, demo and disconnection are explicitly labelled. `ui/work-templates.ts` keeps drafts only in memory and copies an editable task prompt without dispatching work. The office canvas, preferences, sessions and existing panels retain their behavior.

Regression checks for this addition: `npm test -- client/src/ui/work-center-model.test.ts client/src/ui/work-templates.test.ts --maxWorkers=2`, then the full suite, typecheck and build. For isolated browser coverage, run `npx tsx server/test/work-center-ui-server.ts` and pass its printed loopback URL to `node scripts/test-work-center.mjs <url>`. The fixture uses synthetic data and checks all four tabs, direct/native questions, clipboard outcomes, drafts, guarded deliveries, keyboard navigation and five viewport sizes. On Windows it launches a separate headless Chrome; `PLAYWRIGHT_CHANNEL` can select another installed Playwright-supported channel. Screenshots are saved under the system temporary directory in `disserohub-work-center-browser`.

The **Tarefas** section saves manual tasks independently of transcript tasks in `<dataDir>/project-tasks.json`. Project identity comes from a known office room; rooms with saved tasks are restored at startup. Atomic replacement, serialized writes and task revisions prevent partial saves and lost edits between tabs. Invalid saved data fails closed and is preserved. This store assumes one local service owns its data directory. The API is local-only, rejects cross-origin requests and cannot operate in demonstration mode.

Tasks have an owner, priority, dependencies and acceptance criteria. Only an explicit accepted delivery review completes a task; every criterion and dependency must be satisfied. Reviews retain their decision, reason and delivery reference even when a session disappears. The delivery fingerprint identifies the recorded answer and attachment metadata, not a fresh validation of file contents. Editing a completed task reopens it; earlier reviews remain in its history. No task or review dispatches an agent command. Validate persistence/API with `npx vitest run server/tasks/store.test.ts server/http/project-tasks.test.ts --maxWorkers=2` and the browser workflow with `node scripts/test-project-tasks.mjs <fixture-url>`. The Central now has five sections.

Wellbeing accounting clips desktop, idle and agent observations at their freshness deadlines even when frequent dashboard reads keep arriving. Personal time remains the union of observed browser/desktop activity, separate from the union of agent activity. Daily-limit reminders take priority once both limits are due. Foreground tabs announce the visible reminder without consuming the system-notification claim; an eligible background/unfocused tab claims it only when system notifications are enabled and permitted. The settings explain browser permission and the requirement to keep the page open. Demo, replay and disconnected views suppress personal alerts. `scripts/test-wellbeing.mjs <fixture-url>` exercises these flows using synthetic time, desktop signals and notification stubs; real user history is never modified by the browser harness.

Windows tests use two isolated thread workers with transformed-module caching. Fixtures use native paths and separators, preserve POSIX mode assertions only on platforms that support them, and allocate ports accepted by Fetch. Shell integration cases keep bounded process deadlines while accounting for cold Git Bash/Node startup; the Codex permission timeout is measured after its request is registered. Pixel and transcript determinism tests retain full content checks with faster equality paths.

The upstream baseline is official Habblaud v0.11.0. Existing provider, source, identity, and Windows runtime changes remain intact. The workspace refinements are grouped under `client/src/local/`, including feed presentation policy. `client/src/ui/feed-policy.ts` is a stable re-export used by existing integration points. `workspace.css` is loaded after upstream styles, so new styling does not have to be scattered through the original stylesheet.

From DisseroHub 1.0.3, distribution numbers track the reviewed official release. `upstreamReferenceVersion` / `UPSTREAM_REFERENCE_VERSION` record that number; `upstreamVersion` / `UPSTREAM_BASE_VERSION` continue recording the actual integrated baseline. Matching numbers do not imply a full upstream merge. The reviewed official 1.0.3 (`faa1a012b5fbf632c66dc6801c5383e53a542406`) only fixes returning from the World city to an agent request; that flow is absent here. See `docs/UPSTREAM-VERSIONING.md`. The publisher refuses inconsistent version metadata while preserving the separate DisseroHub release channel.

Selective upstream backport in DisseroHub 0.11.3: `99606d5e1ff8da726e72e445665e57c84342d1cc` fixes the legacy clipboard helper in `client/src/ui/dom.ts`. Its temporary textarea belongs inside the focused open dialog, and focus returns to the original control after cleanup. This does not change the upstream baseline or update channel, or include Habblaud World. The opt-in `node --import tsx server/test/clipboard-ui-server.ts` fixture exercises the modern path, legacy fallback inside/outside a native modal, and simulated legacy rejection/exception with synthetic text only. It is not part of the production entry points. In the embedded browser, modern clipboard contents were confirmed; legacy selection, copy events, cleanup and focus were confirmed, while final legacy clipboard contents still require a conventional browser check.

Integration points are `ui/index.ts`, `prefs.ts`, `context.ts`, `sidebar.ts`, `drawer.ts`, `rows.ts`, `widgets.ts`, `settings.ts`, and the additive camera/economy API in `world/api.ts` and `world/index.ts`. Preferences use the existing `habblaud:prefs` key with per-field defaults. Compact panel sizes are temporary; saved user dimensions are retained. Raw activity data is retained; feed filtering and text cleanup affect presentation only.

Inventory without changing anything:

The legal-office presentation adds `local/legal-appearance.ts` for deterministic formal defaults, `local/legal-social.ts` for discussion dialogue and reading preferences, and `art/furniture/legal.ts` for furniture variants using existing footprints. Saved character parts override generated defaults. Project rooms retain six desk spots; the former game lounge becomes the Sala de Convivência, with four seats around a discussion table. Modern SVG controls retain their existing labels and actions. The four appearance choices are Automatic, None, Christmas, and Halloween. Legacy `legal` preferences migrate to None. UI world options enable `legalOffice` independently of the seasonal theme, favoring books and thesis discussions while disabling competitive social activities and shell waiting gags. Real agent status remains intact.

The camera picker measures the selected project name using explicit computed font properties (the font shorthand can be empty with numeric variants). All camera controls stay on one line. The picker uses its measured width within 160–260 px and does not grow to fill the toolbar. Narrow windows can scroll the row horizontally. Integration points also include the art catalog and dispatcher, `layout/core.ts`, `layout/room.ts`, `render/scene.ts`, `render/renderer.ts`, `render/overlay.ts`, `sim/sim.ts`, and `social/social.ts`. The pure upstream appearance generator remains available; the runtime art adapter applies formal defaults consistently to world characters and UI avatars.

`local/readability.css` and `local/readable-typography.ts` enlarge the existing UI hierarchy moderately: Segoe UI, 15 px body text, 18 px section headings, and a 14 px minimum for small labels. The startup adaptation visits local UI stylesheet rules, including media rules; explicit numeric overrides cover shorthands whose serialization is hidden by numeric variants. Dialogs, controls, statistics grids, and settings wrap for larger type. Usage rows have matching line heights and column widths, and provider logos are square. The terminal uses 15 px text. Day statistics reuse the provider-logo account chip, including historical accounts. Help describes the current navigation, feed, account usage, legal-office activities, and command waiting; stage identifiers and timing remain compatible with the upstream model.

Subagents are always listed below their main agent, within the active account/search filters. The caption is informational, with no collapse control. The reception has a window in place of the old sign. The interface uses the official Dissero open-D mark; justice posters use a larger dark silhouette on an ivory field.

The local product is Dissero at `https://dissero.localhost/`. Client and server explicitly select `pt-BR`, and the settings language selector is removed. Dissero SVG, raster favicon/PWA sizes and social preview are included in this public visual distribution. Page metadata, wordmark, notifications, demo activities and user-facing server messages use Dissero. Habblaud remains the upstream engine name and retains compatibility package/plugin identifiers, environment variables, storage keys and the existing data directory. Updates and releases belong exclusively to `brunoflma/disserohub`; the hosted Dissero plugin has its own Cloudflare distribution and is not part of this repository.

`shared/branding.ts` holds a strict allowlist of UI preference keys. Before app startup, `local/branding-origin.ts` transfers those preferences from the old local origin using ephemeral one-use server tickets. Tickets expire after three minutes and are removed after use; values stay out of the URL and server files. Existing destination values win, and source values remain intact. The API requires loopback, an explicit approved Host and matching Origin, rejects unknown keys and oversized input, and is disabled for remote listeners. A failed import cannot initialize replacement defaults; `?dissero-legacy=1` keeps a recovery address available. Real project registration, names, sessions, usage and history remain in the original data location.

The top bar grows with its content. `TopBar` observes its actual height and publishes `--top-h` for the panels and camera; the bar itself uses intrinsic height, avoiding a sizing feedback loop. Account cards keep a 240 px minimum, move to their own row when needed, and support visible horizontal scrolling and keyboard focus. Real and demo accounts share this behavior. Project rooms have four deterministic furniture plans with six workstation spots and clear doors. Reserved slots have a reading nook with two armchairs, a sofa, coffee table, bookshelf, floor lamp, plant and rug, leaving the entrance and center clear. They remain visual placeholders and do not register projects, walkable areas or agent spots. Their former outdoor closure walls are removed rather than layered behind the doorway.

Asynchronous Codex questions can be answered in the agent drawer through `ui/question-replies.ts`, `shared/question-replies.ts` and the guarded local message endpoint. Answers are validated against the current question, keyed to its activity and question index, and retain a receipt across retries. Queued delivery and agent consumption remain distinct; blocking questions still require their owning client. The onboarding package under `docs/onboarding/` prepares native-first installation prompts and synthetic capacity checks; it does not activate the hosted plugin integration or claim clean-install qualification.

The sidebar search includes an Add project button. `ui/projects.ts` provides a modal with recent-folder shortcuts, directory navigation, and a path field. `server/projects/folders.ts` lists directory metadata and atomically persists selected paths in a separate `<dataDir>/projects.json`. Registrations are idempotent, serialized within the process, and capped at 100; listings are capped at 500 directories and omit files and symlinks. The new API requires a loopback connection, a local Host, and the same origin when Origin is supplied. It is unavailable on the remote listener. Registered rooms survive without agents and restart; registration does not launch an agent or create a project directory. Shared folder-response types live in `shared/projects.ts`.

The project dialog also exposes local drive shortcuts independently of the current folder. Windows mounted volume letters come from a read-only `MountedDevices` registry query in `server/projects/roots.ts`, with a one-minute cache, bounded output and a hidden subprocess. Canonical directory checks exclude unavailable historical letters, UNC shares and drive aliases; only root names and paths reach the client. Non-Windows runtimes expose the filesystem root; if discovery fails, manual path entry remains available and the home volume is shown. Existing project persistence and route guards are unchanged.

The common-area layout keeps two reception armchairs plus a usable three-seat sofa, publications, coffee tables and a reading lamp. The bathroom has a usable mirrored vanity, towel/supply cabinets and a low privacy partition, with no bench or chair. `art/furniture/facilities.ts` supplies the three new fixtures with catalog footprints and standard floor anchors. Common and project-room plants occupy corner zones; the reserved-room presentation follows the same placement. Six cafeteria seats remain at one table, and the Sala de Convivência keeps grouped reading/discussion seats. Its label is updated in world overlays, social events, invitations and help, while `core:lounge` and discussion-group IDs remain stable. Reception seats never use the sleeping pose. Idle agents still visit all four common areas, and work resumption, pathfinding, occupancy reservations, and the six desks per project room retain their existing behavior.

```powershell
node scripts/local-customizations.mjs status
```

Export tracked changes, new source modules, and their baseline commit to a new directory outside `integration`:

```powershell
node scripts/local-customizations.mjs export
```

The export contains `tracked.patch`, `new-files/`, and `manifest.json`. It contains source customizations only, not identities, usage, history, TLS certificates, or credentials. A full installation/data backup is still required before an upgrade.

For a future upstream release, fetch the official `upstream` remote and prepare an integration branch in this fork. Reconcile conflicts without replacing the Dissero customizations. Update the recorded upstream baseline, run the validation below and CI, and publish a new Dissero release only after acceptance. Do not reset or overwrite a live customized installation. Its automatic dirty-tree protection must remain enabled.
